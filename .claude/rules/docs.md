# ドキュメント規約

`AGENTS.md`・`README.md`・`.claude/` 配下等のドキュメントは、ソースコード・設定ファイル（SSoT）に追従するものとして書く。

## 書かないこと

- ソースコードや設定ファイルから読み取れる情報。他のファイル・ディレクトリ・リンク・スキルを参照している箇所であれば尚更、その参照先を見れば分かる内容（具体例・項目の列挙・設定値・手順）を重ねて書かない
- `git log` で追える履歴（変更の経緯・過去の議論等）。設計判断の経緯・理由は `docs/adr/` の ADR に書く
- 一般的・慣例的な知識（このリポジトリ固有ではない一般論）
- 特定タスクの一時的な指示（そのタスク限りで、今後も通用する規約ではないもの）

## 原則

- 一文を書くたびに「ソースコード・`git log`・一般知識を見れば自明か？」を自問し、自明なら削る
- 参照先を見ても気づきにくい非自明な事実（命名の不一致、実際の挙動の違い、隠れた制約、設計判断の理由等）は書く価値がある
- 実装を変更したら、それに言及しているドキュメントが食い違っていないか確認する
