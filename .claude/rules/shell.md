# シェルスクリプト規約

`*.sh` は [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html) に従う。

## 主な規約（ツールでは検出されない観点）

- ファイル冒頭に用途を説明するコメントを書く
- 非自明な関数にはヘッダコメント（概要・グローバル変数・引数・出力・返り値）を書く
- 変数展開は `"${var}"` の形で必ずクォートする（例外: `$1` 等の1桁の位置パラメータは波括弧不要）
- 条件分岐は `[ ]`/`test` ではなく `[[ ]]` を使う
- 算術評価は `let`/`expr`/`$[ ]` ではなく `(( ))`/`$(( ))` を使う
- `eval` は使わない
- 複数の関数を持つスクリプトは、全関数をファイル冒頭付近にまとめ、`main` 関数を定義して末尾を `main "$@"` で締める（単純なフックスクリプトはこの限りではない）
- 1行80文字を目安に収める（ファイルパス・URLはこの限りではない）

## このリポジトリでの例外

- shebang は `#!/usr/bin/env bash` を使う（Nix環境では `/bin/bash` が存在しない、または古い場合がある）
- インデント幅は `flake.nix` の shfmt の設定に従う
- `[[ ]]` 内の変数展開は、shfmt の簡略化（`-s`）によりクォートが外されるため、その結果に従う

## 自動チェック

- 整形: `shfmt`（`treefmt`）
- lint: `shellcheck`（`treefmt`）
