# grouping-rules Specification

## Purpose

タブをどのタブグループにまとめるかを決めるルールの内容と保存、および URL がどのルールに一致するかの判定を定める。

## Requirements

### Requirement: ルールの内容

ルールは、グループ名・グループの色・条件の一覧を持たなければならない（MUST）。色は Chrome のタブグループの色（grey・blue・red・yellow・green・pink・purple・cyan・orange）のいずれかでなければならない（MUST）。条件は種類（部分一致・正規表現）と値を持たなければならない（MUST）。ルールは順番を持つ一覧として扱い、一覧での位置が優先度とタブバー上の並びを表さなければならない（MUST）。

#### Scenario: 1つのルールに複数の条件を持つ

- **WHEN** ルール「開発」に部分一致 `github.com` と部分一致 `gitlab.com` の2つの条件を設定する
- **THEN** ルール「開発」は2つの条件を持つ

### Requirement: ルールの保存

ルールの一覧は拡張機能のローカルストレージに保存し、ブラウザを再起動しても保たなければならない（MUST）。ルールが1つも保存されていないときは、空の一覧として扱わなければならない（MUST）。

#### Scenario: 初回インストール時

- **WHEN** 拡張機能をインストールした直後にルールの一覧を読み込む
- **THEN** 空の一覧が返る

#### Scenario: 再起動後も残る

- **WHEN** ルールを保存してからブラウザを再起動する
- **THEN** 保存したルールの一覧が同じ順番で読み込まれる

### Requirement: 部分一致の条件

部分一致の条件は、値がタブの URL 全体のどこかに含まれるときに一致しなければならない（MUST）。大文字・小文字は区別してはならない（MUST NOT）。値が空の条件はどの URL にも一致してはならない（MUST NOT）。

#### Scenario: URL に値が含まれる

- **WHEN** 条件が部分一致 `github.com` で、URL が `https://github.com/wire2c7/tabherd` である
- **THEN** 条件に一致する

#### Scenario: 大文字・小文字の違い

- **WHEN** 条件が部分一致 `GitHub.com` で、URL が `https://github.com/` である
- **THEN** 条件に一致する

#### Scenario: 値が空

- **WHEN** 条件が部分一致で値が空文字列である
- **THEN** どの URL にも一致しない

### Requirement: 正規表現の条件

正規表現の条件は、値を `u` フラグだけを付けた JavaScript の正規表現として URL 全体を検索し（大文字・小文字は区別する）、見つかったときに一致しなければならない（MUST）。構文が不正な値や空の値は、例外を出さずにどの URL にも一致しない扱いにしなければならない（MUST）。

#### Scenario: 正規表現に一致する

- **WHEN** 条件が正規表現 `^https://[^/]+\.example\.com/` で、URL が `https://docs.example.com/guide` である
- **THEN** 条件に一致する

#### Scenario: 構文が不正

- **WHEN** 条件が正規表現 `(` である
- **THEN** どの URL にも一致せず、判定の処理は続行される

### Requirement: ルールの有効性

グループ名が空（前後の空白を除いて空）のルールと、グループ名が一覧で上にあるルールと同じルールは無効とし、判定の対象にしてはならない（MUST NOT）。

#### Scenario: グループ名が空

- **WHEN** グループ名が空のルールの条件に一致する URL を判定する
- **THEN** そのルールには一致しないものとして扱う

#### Scenario: グループ名の重複

- **WHEN** 1番目と3番目のルールのグループ名がどちらも「開発」である
- **THEN** 3番目のルールは判定の対象にならない

### Requirement: 一致するルールの決定

URL に対して、条件のいずれか1つに一致する有効なルールのうち、一覧で最も上にあるものを、その URL が一致するルールとしなければならない（MUST）。どのルールにも一致しないときは「一致なし」としなければならない（MUST）。

#### Scenario: 複数のルールに一致する

- **WHEN** 1番目のルール「業務」と2番目のルール「開発」の両方の条件に URL が一致する
- **THEN** URL は「業務」に一致する

#### Scenario: どのルールにも一致しない

- **WHEN** URL がどのルールの条件にも一致しない
- **THEN** 一致なしになる

### Requirement: 保存されたルールの読み込み

保存されたルールの一覧の形が壊れていても、例外を出さずに読める部分を使わなければならない（MUST）。保存値が一覧でなければ、空の一覧として扱わなければならない（MUST）。ID かグループ名が読めないルールと、ID が上のルールと同じルールは除かなければならない（MUST）。条件の一覧が読めないルールは条件を持たないものとし、種類か値が読めない条件はその条件だけを除かなければならない（MUST）。色が読めないルールの色は grey としなければならない（MUST）。読み込みで保存されたルールを書き換えてはならない（MUST NOT）。バックグラウンドの処理は、壊れた値を読んだときに警告のログを残さなければならず（MUST）、壊れていない値を読むまでは、バックグラウンドの処理が止まって起き直しても、ブラウザを起動し直すまで同じ警告を繰り返してはならない（MUST NOT）。

#### Scenario: 条件の一覧が壊れている

- **WHEN** ルール「開発」の条件の一覧が `null` で、ルール「資料」（部分一致 `.org`）が正しく保存されている状態で、`https://example.org/` のタブを判定する
- **THEN** 判定は例外を出さずに続き、タブは「資料」に一致する

#### Scenario: 保存値が一覧でない

- **WHEN** 保存されたルールの値が文字列である
- **THEN** ルールの一覧は空として扱われる

#### Scenario: 壊れた値を読み続ける

- **WHEN** 保存されたルールが壊れた状態のまま、バックグラウンドの処理がルールを何度も読む
- **THEN** 警告のログは最初の1回だけ残る

#### Scenario: バックグラウンドの処理が起き直す

- **WHEN** 保存されたルールが壊れた状態で警告のログが残った後、操作が無くバックグラウンドの処理が止まり、タブを開いて起き直す
- **THEN** 警告のログは増えない
