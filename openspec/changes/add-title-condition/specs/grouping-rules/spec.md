# Spec Delta

## MODIFIED Requirements

### Requirement: ルールの内容

ルールは、グループ名・グループの色・条件の一覧を持たなければならない（MUST）。色は Chrome のタブグループの色（grey・blue・red・yellow・green・pink・purple・cyan・orange）のいずれかでなければならない（MUST）。条件は対象（URL・タイトル）・種類（部分一致・正規表現）と値を持たなければならない（MUST）。対象の指定がない条件は URL を対象とする条件として扱わなければならない（MUST）。ルールは順番を持つ一覧として扱い、一覧での位置が優先度とタブバー上の並びを表さなければならない（MUST）。

#### Scenario: 1つのルールに複数の条件を持つ

- **WHEN** ルール「開発」に部分一致 `github.com` と部分一致 `gitlab.com` の2つの条件を設定する
- **THEN** ルール「開発」は2つの条件を持つ

#### Scenario: タイトルを対象にした条件を持つ

- **WHEN** ルール「開発」にタイトルを対象にした部分一致 `Pull Request` の条件を設定する
- **THEN** ルール「開発」はタイトルを対象にした条件を持つ

#### Scenario: 対象の指定がない既存の条件

- **WHEN** 対象の指定がない部分一致 `github.com` の条件を読み込む
- **THEN** その条件は URL を対象にした条件として扱われる

### Requirement: 部分一致の条件

部分一致の条件は、値が対象（URL・タイトル）の文字列全体のどこかに含まれるときに一致しなければならない（MUST）。大文字・小文字は区別してはならない（MUST NOT）。値が空の条件はどの対象にも一致してはならない（MUST NOT）。

#### Scenario: URL に値が含まれる

- **WHEN** 条件が URL を対象にした部分一致 `github.com` で、URL が `https://github.com/wire2c7/tabherd` である
- **THEN** 条件に一致する

#### Scenario: タイトルに値が含まれる

- **WHEN** 条件がタイトルを対象にした部分一致 `Pull Request` で、タブのタイトルが `Add title condition by wire2c7 · Pull Request #99` である
- **THEN** 条件に一致する

#### Scenario: 大文字・小文字の違い

- **WHEN** 条件が部分一致 `GitHub.com` で、URL が `https://github.com/` である
- **THEN** 条件に一致する

#### Scenario: 値が空

- **WHEN** 条件が部分一致で値が空文字列である
- **THEN** どの対象にも一致しない

### Requirement: 正規表現の条件

正規表現の条件は、値を `u` フラグだけを付けた JavaScript の正規表現として対象（URL・タイトル）の文字列全体を検索し（大文字・小文字は区別する）、見つかったときに一致しなければならない（MUST）。構文が不正な値や空の値は、例外を出さずにどの対象にも一致しない扱いにしなければならない（MUST）。

#### Scenario: 正規表現に一致する

- **WHEN** 条件が URL を対象にした正規表現 `^https://[^/]+\.example\.com/` で、URL が `https://docs.example.com/guide` である
- **THEN** 条件に一致する

#### Scenario: タイトルの正規表現に一致する

- **WHEN** 条件がタイトルを対象にした正規表現 `^\[.+\]` で、タブのタイトルが `[開発] チケット一覧` である
- **THEN** 条件に一致する

#### Scenario: 構文が不正

- **WHEN** 条件が正規表現 `(` である
- **THEN** どの対象にも一致せず、判定の処理は続行される

### Requirement: 一致するルールの決定

タブの URL とタイトルに対して、条件のいずれか1つに一致する有効なルールのうち、一覧で最も上にあるものを、そのタブが一致するルールとしなければならない（MUST）。条件は、それぞれの対象（URL・タイトル）の値に対して判定しなければならない（MUST）。どのルールにも一致しないときは「一致なし」としなければならない（MUST）。タブのタイトルが未確定（取得できない）ときは、タイトルを対象にした条件はどの値にも一致しないものとして扱わなければならない（MUST）。

#### Scenario: 複数のルールに一致する

- **WHEN** 1番目のルール「業務」と2番目のルール「開発」の両方の条件に URL が一致する
- **THEN** URL は「業務」に一致する

#### Scenario: URL とタイトルの条件を組み合わせたルールに一致する

- **WHEN** ルール「開発」が URL を対象にした部分一致 `github.com` とタイトルを対象にした部分一致 `Pull Request` の条件を持ち、タブの URL が `https://github.com/wire2c7/tabherd/pull/99`、タイトルが `Add title condition by wire2c7 · Pull Request #99` である
- **THEN** タブは「開発」に一致する

#### Scenario: どのルールにも一致しない

- **WHEN** URL とタイトルがどのルールの条件にも一致しない
- **THEN** 一致なしになる

#### Scenario: タイトルが未確定

- **WHEN** タイトルを対象にした部分一致 `読み込み中` の条件があり、新しく開いたタブのタイトルがまだ取得できていない
- **THEN** その条件はこの時点のタブに一致しない

### Requirement: 保存されたルールの読み込み

保存されたルールの一覧の形が壊れていても、例外を出さずに読める部分を使わなければならない（MUST）。保存値が一覧でなければ、空の一覧として扱わなければならない（MUST）。ID かグループ名が読めないルールと、ID が上のルールと同じルールは除かなければならない（MUST）。条件の一覧が読めないルールは条件を持たないものとし、種類か値が読めない条件はその条件だけを除かなければならない（MUST）。対象が読めない条件は URL を対象にした条件として扱わなければならない（MUST）。色が読めないルールの色は grey としなければならない（MUST）。読み込みで保存されたルールを書き換えてはならない（MUST NOT）。バックグラウンドの処理は、壊れた値を読んだときに警告のログを残さなければならず（MUST）、壊れていない値を読むまでは、バックグラウンドの処理が止まって起き直しても、ブラウザを起動し直すまで同じ警告を繰り返してはならない（MUST NOT）。

#### Scenario: 条件の一覧が壊れている

- **WHEN** ルール「開発」の条件の一覧が `null` で、ルール「資料」（部分一致 `.org`）が正しく保存されている状態で、`https://example.org/` のタブを判定する
- **THEN** 判定は例外を出さずに続き、タブは「資料」に一致する

#### Scenario: 保存値が一覧でない

- **WHEN** 保存されたルールの値が文字列である
- **THEN** ルールの一覧は空として扱われる

#### Scenario: 対象が読めない条件

- **WHEN** 条件の対象の値が `"body"` のような不正な値である
- **THEN** その条件は URL を対象にした条件として扱われる

#### Scenario: 壊れた値を読み続ける

- **WHEN** 保存されたルールが壊れた状態のまま、バックグラウンドの処理がルールを何度も読む
- **THEN** 警告のログは最初の1回だけ残る

#### Scenario: バックグラウンドの処理が起き直す

- **WHEN** 保存されたルールが壊れた状態で警告のログが残った後、操作が無くバックグラウンドの処理が止まり、タブを開いて起き直す
- **THEN** 警告のログは増えない
