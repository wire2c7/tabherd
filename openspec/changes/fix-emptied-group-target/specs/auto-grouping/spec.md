# Spec Delta

## MODIFIED Requirements

### Requirement: タブの判定とグループ化

タブの URL が変わったとき（新しく開いたタブの URL が決まったときを含む）と、タブが別のウィンドウへ移されたとき、そのタブを判定し直さなければならない（MUST）。タブが一致したルールのグループが同じウィンドウにあればそこへ入れ、なければルールのグループ名・色で新しく作って入れなければならない（MUST）。同じ判定で元のタブがすべて外れる・別のグループへ移るグループは、空になって消えるため、入れる先にしてはならない（MUST NOT）。すでにそのグループに入っているタブは動かしてはならない（MUST NOT）。

#### Scenario: 新しく開いたタブ

- **WHEN** ルール「開発」（部分一致 `github.com`、色 blue）があり、`https://github.com/` を新しいタブで開く
- **THEN** タブは「開発」という名前で色が blue のタブグループに入る

#### Scenario: 既存のグループに加わる

- **WHEN** ウィンドウに「開発」のグループがあり、同じウィンドウで「開発」に一致するタブを開く
- **THEN** タブは既存の「開発」のグループに入り、新しいグループは作られない

#### Scenario: 別のウィンドウへ移す

- **WHEN** 「開発」のグループに入っているタブを、別のウィンドウへドラッグで移す
- **THEN** タブは移した先のウィンドウの「開発」のグループに入る（なければ作られる）

#### Scenario: 元のタブがすべて外れるグループ

- **WHEN** ルール「資料」（部分一致 `.org`）があり、「資料」のグループにはどのルールにも一致しないタブだけが入っている。すべてのタブを判定し直すとき、同じウィンドウに `https://example.org/` のタブがある
- **THEN** 一致しないタブはグループから外れ、`https://example.org/` のタブは「資料」という名前のグループに入る

#### Scenario: 元のタブがすべて別のグループへ移るグループ

- **WHEN** ルール「開発」（部分一致 `github`）と「資料」（部分一致 `.org`）があり、「資料」のグループには `https://github.com/` のタブだけが、「開発」のグループには別の `https://github.com/` のタブが入っている。すべてのタブを判定し直すとき、同じウィンドウに `https://example.org/` のタブがある
- **THEN** 「資料」のグループの `https://github.com/` のタブは「開発」のグループへ移り、`https://example.org/` のタブは「資料」という名前のグループに入る
