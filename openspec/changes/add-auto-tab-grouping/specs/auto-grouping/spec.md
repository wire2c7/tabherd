# Spec Delta

## Purpose

ルールに従ってタブを自動でタブグループに入れ・外し、タブバー上のグループをルールの順に並べる、バックグラウンドの振る舞いを定める。

## ADDED Requirements

### Requirement: 管理対象のグループ

各ウィンドウで、タイトルが有効なルールのグループ名と完全に一致するタブグループを、そのルールのグループ（管理対象）としなければならない（MUST）。それ以外のタブグループは管理対象にせず、そのタブを移動・解除してはならない（MUST NOT）。タブグループはウィンドウごとに作り、ウィンドウをまたいでタブを移動してはならない（MUST NOT）。

#### Scenario: 手動で作ったグループのタブ

- **WHEN** ルールに一致する URL のタブが、どのルールのグループ名とも異なるタイトルのタブグループに入っている
- **THEN** そのタブは移動されない

#### Scenario: 別のウィンドウ

- **WHEN** ウィンドウ A にルール「開発」のグループがあり、ウィンドウ B で「開発」に一致するタブを開く
- **THEN** ウィンドウ B に「開発」のグループが作られ、タブはそこに入る

#### Scenario: 同名のグループが複数ある

- **WHEN** ウィンドウに「開発」のグループが2つあり、同じウィンドウで「開発」に一致するタブを開く
- **THEN** タブはタブバーで左にある「開発」のグループに入る。すでに右の「開発」のグループに入っているタブは動かされない

### Requirement: タブの判定とグループ化

タブの URL が変わったとき（新しく開いたタブの URL が決まったときを含む）と、タブが別のウィンドウへ移されたとき、そのタブを判定し直さなければならない（MUST）。タブが一致したルールのグループが同じウィンドウにあればそこへ入れ、なければルールのグループ名・色で新しく作って入れなければならない（MUST）。すでにそのグループに入っているタブは動かしてはならない（MUST NOT）。

#### Scenario: 新しく開いたタブ

- **WHEN** ルール「開発」（部分一致 `github.com`、色 blue）があり、`https://github.com/` を新しいタブで開く
- **THEN** タブは「開発」という名前で色が blue のタブグループに入る

#### Scenario: 既存のグループに加わる

- **WHEN** ウィンドウに「開発」のグループがあり、同じウィンドウで「開発」に一致するタブを開く
- **THEN** タブは既存の「開発」のグループに入り、新しいグループは作られない

#### Scenario: 別のウィンドウへ移す

- **WHEN** 「開発」のグループに入っているタブを、別のウィンドウへドラッグで移す
- **THEN** タブは移した先のウィンドウの「開発」のグループに入る（なければ作られる）

### Requirement: 一致しなくなったタブ

管理対象のグループに入っているタブの URL が変わり、別のルールに一致したときはそのルールのグループへ移し、どのルールにも一致しなくなったときはグループから外さなければならない（MUST）。

#### Scenario: 別のルールに一致する URL へ移動する

- **WHEN** 「開発」のグループに入っているタブが、ルール「資料」に一致する URL へ移動する
- **THEN** タブは「資料」のグループへ移る

#### Scenario: どのルールにも一致しない URL へ移動する

- **WHEN** 「開発」のグループに入っているタブが、どのルールにも一致しない URL へ移動する
- **THEN** タブはグループから外れる

### Requirement: 対象外のタブ

ピン留めされたタブは判定の対象にせず、グループに入れてはならない（MUST NOT）。

#### Scenario: ピン留めされたタブ

- **WHEN** ルールに一致する URL のタブがピン留めされている
- **THEN** タブはグループに入らない

### Requirement: 全体の判定し直し

拡張機能のインストール・更新時、ブラウザの起動時、ルールの一覧が変わったときに、すべてのウィンドウのすべてのタブを判定し直さなければならない（MUST）。

#### Scenario: ルールを追加する

- **WHEN** 開いているタブに一致するルールを追加する
- **THEN** 開いているタブがそのルールのグループにまとまる

#### Scenario: インストール直後

- **WHEN** ルールが保存されている状態で拡張機能を更新する
- **THEN** 開いているタブがルールに従ってまとまる

### Requirement: ルールの変更の反映

ルールのグループ名や色を変えたときは、そのルールの既存のグループのタイトル・色を新しい値に変えなければならない（MUST）。ルールを削除したとき（グループ名を空にして無効になったときを含む）は、そのルールのグループに入っていたタブを判定し直し、ほかのルールに一致すればそのルールのグループへ移し、一致しなければグループから外さなければならない（MUST）。

#### Scenario: グループ名を変える

- **WHEN** ルール「開発」のグループ名を「Dev」に変える
- **THEN** 既存の「開発」のグループのタイトルが「Dev」に変わり、タブはそのまま入っている

#### Scenario: 色を変える

- **WHEN** ルール「開発」の色を blue から red に変える
- **THEN** 既存の「開発」のグループの色が red に変わる

#### Scenario: ルールを削除する

- **WHEN** ルール「開発」を削除する
- **THEN** 「開発」のグループに入っていたタブは、ほかのルールに一致しなければグループから外れる

#### Scenario: グループ名を空にする

- **WHEN** ルール「開発」のグループ名を空にする
- **THEN** 「開発」のグループに入っていたタブは、ほかのルールに一致しなければグループから外れる

### Requirement: タブバー上のグループの並び

各ウィンドウで、管理対象のグループを、ピン留めされたタブの直後からルールの一覧の順に並べなければならない（MUST）。管理対象でないタブ・タブグループは、それらの後ろに元の相対的な順番のまま置かなければならない（MUST）。並びがすでに正しいときは、グループを移動してはならない（MUST NOT）。

#### Scenario: ルールの順に並ぶ

- **WHEN** ルールの一覧が「業務」「開発」の順で、タブバーに「開発」「業務」の順でグループがある
- **THEN** タブバー上のグループは「業務」「開発」の順になる

#### Scenario: ルールの順番を変える

- **WHEN** ルールの一覧を「開発」「業務」の順に並び替える
- **THEN** タブバー上のグループも「開発」「業務」の順になる

#### Scenario: ピン留めされたタブがある

- **WHEN** ウィンドウにピン留めされたタブがある
- **THEN** 管理対象のグループはピン留めされたタブの直後から並ぶ

#### Scenario: 管理対象でないタブ・グループがある

- **WHEN** タブバーに、グループに入っていないタブ・手動で作ったグループ・ルール「開発」のグループの順に並んでいる
- **THEN** 「開発」のグループが先頭に移り、グループに入っていないタブ・手動で作ったグループはその後ろに同じ順のまま並ぶ

#### Scenario: 並びがすでに正しい

- **WHEN** タブバー上のグループがすでにルールの順に、ピン留めされたタブの直後から並んでいる
- **THEN** グループは移動されない
