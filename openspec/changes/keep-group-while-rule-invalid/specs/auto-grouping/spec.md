# Spec Delta

## MODIFIED Requirements

### Requirement: 管理対象のグループ

各ウィンドウで、タイトルが有効なルールのグループ名と完全に一致するタブグループを、そのルールのグループ（管理対象）としなければならない（MUST）。それ以外のタブグループは管理対象にせず、そのタブを移動・解除してはならない（MUST NOT）。無効なルールが持ち続けるタイトル（「ルールの変更の反映」）のタブグループも管理対象にしない。タブグループはウィンドウごとに作り、ウィンドウをまたいでタブを移動してはならない（MUST NOT）。

#### Scenario: 手動で作ったグループのタブ

- **WHEN** ルールに一致する URL のタブが、どのルールのグループ名とも異なるタイトルのタブグループに入っている
- **THEN** そのタブは移動されない

#### Scenario: 別のウィンドウ

- **WHEN** ウィンドウ A にルール「開発」のグループがあり、ウィンドウ B で「開発」に一致するタブを開く
- **THEN** ウィンドウ B に「開発」のグループが作られ、タブはそこに入る

#### Scenario: 同名のグループが複数ある

- **WHEN** ウィンドウに「開発」のグループが2つあり、同じウィンドウで「開発」に一致するタブを開く
- **THEN** タブはタブバーで左にある「開発」のグループに入る。すでに右の「開発」のグループに入っているタブは動かされない

### Requirement: 全体の判定し直し

拡張機能のインストール・更新時、ブラウザの起動時、ルールの一覧が変わったときに、すべてのウィンドウのすべてのタブを判定し直さなければならない（MUST）。インストール・更新時とブラウザの起動時は、ルールが持っているグループのタイトルの記録とルールの名前が食い違っていれば、ルールの変更と同じくグループのタイトル・色を変えなければならない（MUST）。名前が同じで色だけが違うグループは、利用者が手で変えた色を保つため変えない。

#### Scenario: ルールを追加する

- **WHEN** 開いているタブに一致するルールを追加する
- **THEN** 開いているタブがそのルールのグループにまとまる

#### Scenario: インストール直後

- **WHEN** ルールが保存されている状態で拡張機能を更新する
- **THEN** 開いているタブがルールに従ってまとまる

### Requirement: ルールの変更の反映

ルールが持っているグループのタイトルを端末に記録し、ブラウザを起動し直しても保たなければならない（MUST）。有効なルールのタイトルはグループ名とし、ルールが無効になった（グループ名を空にした、ほかのルールのタイトルと名前が重なった）ときは、無効になる前のタイトルを持ち続けなければならない（MUST）。

ルールのグループ名や色を変えたときと、無効なルールが有効に戻ったときは、そのルールが持っていたタイトルのグループのタイトル・色を新しい値に変えなければならない（MUST）。持ち主が削除されたタイトルを、同じグループ名のルールが引き継いだときは、そのグループの色を引き継いだルールの色に変えなければならない（MUST）。無効なルールが持ち続けるタイトルのグループは、タブを移動・解除してはならず（MUST NOT）、そのルールの条件に一致するタブを入れてもならない（MUST NOT）。ルールを削除したときは、そのルールのグループに入っていたタブを判定し直し、ほかのルールに一致すればそのルールのグループへ移し、一致しなければグループから外さなければならない（MUST）。

#### Scenario: グループ名を変える

- **WHEN** ルール「開発」のグループ名を「Dev」に変える
- **THEN** 既存の「開発」のグループのタイトルが「Dev」に変わり、タブはそのまま入っている

#### Scenario: 色を変える

- **WHEN** ルール「開発」の色を blue から red に変える
- **THEN** 既存の「開発」のグループの色が red に変わる

#### Scenario: ルールを削除する

- **WHEN** ルール「開発」を削除する
- **THEN** 「開発」のグループに入っていたタブは、ほかのルールに一致しなければグループから外れる

#### Scenario: グループ名を空にする

- **WHEN** ルール「開発」のグループ名を空にする
- **THEN** 「開発」のグループとその中のタブ・位置は変わらず、「開発」の条件に一致するタブを新しく開いてもグループに入らない

#### Scenario: グループ名を打ち直す

- **WHEN** ルール「開発」のグループ名を空にした後、「Dev」と入力する
- **THEN** 既存の「開発」のグループのタイトルが「Dev」に変わり、タブはそのまま入っている

#### Scenario: 空のままブラウザを起動し直す

- **WHEN** ルール「開発」のグループ名を空にしたままブラウザを起動し直し、その後「Dev」と入力する
- **THEN** 起動し直した後も「開発」のグループは変わらず、入力すると「開発」のグループのタイトルが「Dev」に変わる

#### Scenario: 名前を入れ替える

- **WHEN** ルール「開発」「資料」のグループ名を「資料」「開発」に入れ替える
- **THEN** 「開発」のグループのタイトルが「資料」に、「資料」のグループのタイトルが「開発」に変わり、タブはそのまま入っている

#### Scenario: ほかのルールの名前を通って打ち直す

- **WHEN** ルール「開発」「業務」がこの順にあり、「開発」のグループ名を「業務」を通って「業務2」に変える
- **THEN** 「業務」のグループはそのままで、「開発」のグループのタイトルが「業務2」に変わる

### Requirement: タブバー上のグループの並び

各ウィンドウで、管理対象のグループと無効なルールが持ち続けるタイトルのグループを、ピン留めされたタブの直後からルールの一覧の順に並べなければならない（MUST）。それ以外のタブ・タブグループは、それらの後ろに元の相対的な順番のまま置かなければならない（MUST）。並びがすでに正しいときは、グループを移動してはならない（MUST NOT）。

#### Scenario: ルールの順に並ぶ

- **WHEN** ルールの一覧が「業務」「開発」の順で、タブバーに「開発」「業務」の順でグループがある
- **THEN** タブバー上のグループは「業務」「開発」の順になる

#### Scenario: ルールの順番を変える

- **WHEN** ルールの一覧を「開発」「業務」の順に並び替える
- **THEN** タブバー上のグループも「開発」「業務」の順になる

#### Scenario: ピン留めされたタブがある

- **WHEN** ウィンドウにピン留めされたタブがある
- **THEN** 管理対象のグループはピン留めされたタブの直後から並ぶ

#### Scenario: 管理対象でないタブ・グループがある

- **WHEN** タブバーに、グループに入っていないタブ・手動で作ったグループ・ルール「開発」のグループの順に並んでいる
- **THEN** 「開発」のグループが先頭に移り、グループに入っていないタブ・手動で作ったグループはその後ろに同じ順のまま並ぶ

#### Scenario: 並びがすでに正しい

- **WHEN** タブバー上のグループがすでにルールの順に、ピン留めされたタブの直後から並んでいる
- **THEN** グループは移動されない

#### Scenario: 無効なルールのグループ

- **WHEN** ルールの一覧が「開発」「業務」の順で、「開発」のグループ名を空にしている
- **THEN** 「開発」のグループは「業務」のグループより前に置かれたままになる
