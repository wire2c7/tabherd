# Design

## Context

- Chrome のタブグループが持てるのはタイトルと色だけで、拡張機能の値を付けられない。グループとルールの結び付きはタイトルで決めている（`planGrouping` の管理対象のタイトル）
- ルールの変更は `debounceChanges` で 300ms まとめ、`diffRules` で変更前後のルールを ID で突き合わせて反映する。無効になったルールの名前は `retiredNames` に入り、そのグループのタブは外される
- 名前の重複は、一覧で上のルールが有効になる（`findRuleProblems`）

## Goals / Non-Goals

**Goals:**

- 打ち直しの途中で一時的に無効になったルールのグループを壊さない（ブラウザを起動し直しても）
- 名前を打ち直した後、同じグループのタイトルを変える

**Non-Goals:**

- 待ち時間のあいだのタブのイベントの競合（#67）
- 使われないルールの通知（別の Issue）

## Decisions

### ルールが持っているグループのタイトルを記録する

ルールの ID から、そのルールのグループのタイトルへの対応（`RuleTitles`）を、反映のたびに background が `local:ruleGroupTitles` に保存する。有効なルールは今の名前、無効なルールは無効になる前のタイトルを持ち続ける。ルールを削除すると対応も消える。

- 採用理由: グループに印を付けられないため、無効なあいだも「どのタイトルのグループがこのルールのものか」を覚えておく必要がある。ブラウザを起動し直した後も続けるため、`session` ではなく `local` に置く
- 記録が無いルール（この変更より前に作ったルール等）は、変更前のルールが有効ならその名前を持っていたものとみなす。最初の反映で記録される
- 却下した案: ルールの保存値（`local:rules`）に持たせる。設定画面と background の両方が書くことになり、書き込みが競合する

### 無効なルールのグループは「持ち続けるタイトル」として扱う

無効なルールが持ち続けるタイトルのグループは、管理対象にしない（中のタブは判定しない）が、並びではそのルールの位置に置く。

### 名前が重なったときは、すでにそのタイトルを持っているルールを有効にする

グループ名が、ほかのルールが記録で持っているタイトルと同じルールを無効にする。ただし、互いに相手のタイトルを名前にしたルール（名前の入れ替え）は、どれも有効にして、グループのタイトルを入れ替える（無効にすると、3つ目の名前を経由しない限り抜け出せない）。名前を空にして無効なあいだ持ち続けるタイトルも含める（含めないと、別のルールがそのタイトルを名前にしたとき、同じタイトルのグループが2つになる）。どのルールも持っていない名前が重なったときは、一覧で上のルールを有効にする。設定画面も記録を読んで同じ判定をし、エラーの文言は「ほかのルールが使っているグループ名」にする（名前を空にしたルールのタイトルと重なったときは、同じ名前のルールが画面に見えないため）。

- 採用理由: 上のルールが下のルールの名前を一時的に通ったとき、上のルールを有効にすると、そのグループのタイトルが下のルールと同じになり、以後は区別できなくなる
- 却下した案: 今どおり上のルールを有効にし、既知の制限とする

### 反映は「記録 → 新しいルール」の差分にする

`diffRules` は変更前のルール一覧に加えて記録を受け取り、新しい記録・タイトルの変更・使われなくなったタイトルを返す。有効なルールの記録のタイトルが名前と違うか、変更前に無効だったか、色が変わったときに、記録のタイトルのグループを新しい名前・色に変える。有効性は記録で決まり、記録は有効性で決まるため、記録が変わらなくなるまで求め直す（タイトルを手放したルールと同じ名前の別のルールが、同じ反映で有効になる）。持ち主が削除したタイトルを引き継いだルールは、そのグループの色を自分の色に変える。起動時の判定し直しも同じ差分で行い、記録と名前がずれていれば直す。記録は色を持たないため、起動時に色だけのずれは直さない（利用者が手で変えたグループの色を保つ）。

### 設定画面は記録を読むだけにする

記録を書くのは background だけにする。設定画面は記録を読み、変わったら読み直す。

## Risks / Trade-offs

- [名前を空にしたまま残したルールのグループは、ルールを削除するまで残る] → 使われないルールの通知（別の Issue）で気づけるようにする
- [記録が書かれる前（反映の 300ms の待ちのあいだ）は、重複の判定が上のルール優先になる] → 新しく作ったルール同士の重複に限られ、既存のグループは記録済み
- [記録の保存が失敗すると、次の反映で古い記録を使う] → 反映の処理は失敗をログに出して続け、次の反映で書き直す
