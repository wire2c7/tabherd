# Proposal

## Why

設定画面はグループ名を1文字入力するたびに保存し、background は 300ms 待ってから反映する。打ち直しの途中で名前が空になったり、ほかのルールと同じ名前を一時的に通ったりすると、ルールが無効になってグループのタブがすべて外れ、続けて名前を入れるとグループが作り直される（#70）。上のルールが下のルールの名前を通ると、同じ名前のグループが2つになり、続けて名前を変えると両方のグループが変わる。

## What Changes

- 名前が空か、ほかのルールと重なって無効なあいだは、そのルールの既存のグループに触れない（ルールの順の位置に置いたまま、中のタブを動かさず、新しいタブも入れない）
- 有効な名前に戻ったら、そのグループのタイトル・色を新しい名前に変える
- ルールが持っているグループのタイトルを端末（`local:ruleGroupTitles`）に記録し、ブラウザを起動し直しても同じように扱う
- 名前が重なったときは、すでにその名前のグループを持っているルールを有効にし、後からその名前にしたルールを無効にする。どちらも持っていなければ、今どおり上のルールを有効にする
- 名前を空にしたルールが持ち続けるタイトルも、そのルールが持っているものとして扱う
- 設定画面の重複のエラーを、上のルールと同じ旨から、ほかのルールが使っている旨に変える

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `auto-grouping`: 「管理対象のグループ」「全体の判定し直し」「ルールの変更の反映」「タブバー上のグループの並び」
- `grouping-rules`: 「ルールの有効性」
- `rule-settings-ui`: 「入力の検証」

## Impact

- `utils/rules/types.ts`・`parse.ts`・`storage.ts`: ルールが持っているグループのタイトル（`RuleTitles`）の型・読み込み・保存
- `utils/rules/match.ts`: 有効性の判定にタイトルを使う。無効なルールが持ち続けるタイトルと、ルールの順のタイトルの一覧
- `utils/grouping/rule-change.ts`・`regroup.ts`・`plan.ts`・`order.ts`: タイトルを使った差分・判定・並び
- `entrypoints/background/grouping.ts`: タイトルを読み、反映した後に保存する
- `components/rule-settings/`: タイトルを読んで重複を判定し、エラーの文言を変える
- `entrypoints/popup/app.tsx`・`entrypoints/options/app.tsx`: タイトルの保存先を渡す
