# 0012. import にパスのエイリアスを使わない

- ステータス：Accepted
- 日付：2026-09-29
- 関連 Issue：#14

## コンテキスト

WXT は `wxt prepare` で生成する `.wxt/tsconfig.json` の `paths` と Vite の設定に、プロジェクトのルートを指すエイリアス（`@`・`@/*`・`~`・`~/*`）を定義する。自分たちで設定していなくても `import ... from "@/utils/..."` と書けてしまい、実装のなかで相対パスとエイリアスが混在し始めていた。

## 検討した選択肢

- **エイリアスを使う**：深い階層からでも import のパスが短く、ファイルを移動しても import を書き換えずに済む。一方、TypeScript・Vite・Vitest・エディタのそれぞれがエイリアスを解決できる必要があり、エイリアスの定義を管理する対象が増える。WXT の生成物に依存するため、WXT を外すと import が壊れる
- **相対パスに揃える**：ツールの設定なしにどこでも解決でき、ファイルどうしの位置関係が import から読み取れる。一方、ディレクトリをまたぐ import は `../` が続いて長くなる

## 決定

import は相対パスで書き、パスのエイリアスは使わない。エイリアスを管理する対象を増やさず、WXT の生成物に import の解決を依存させないため。

WXT のエイリアスは生成物にあって設定から外せないため、Oxlint の `eslint/no-restricted-imports` で `@`・`~` で始まるパスの import を禁じる。

## 結果

- `pnpm lint` がエイリアスでの import を検出する。スコープ付きの npm パッケージ（`@wxt-dev/...` 等）は対象外
- ディレクトリをまたぐ import は `../` で書く。階層が深くなって読みにくくなるようなら、エイリアスではなくディレクトリの構成を見直す
