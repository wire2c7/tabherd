# 0024. TSDocは構造化タグを使い、テストはit単位で前提・検証コメントを書く

- ステータス：Accepted
- 日付：2026-10-06
- 関連 Issue：#78

## コンテキスト

`utils/`・`components/`・`entrypoints/` には自由形式の `/** ... */` コメントはあるが、`@param`・`@returns`・`@remarks` 等の構造化された TSDoc タグは使っていない。テストコードにも、各 `it`/`test` 単位での前提・検証項目のコメントは無い。両方とも規約が無いまま書き方が揃っていない。

## 検討した選択肢

### TSDoc の書き方

- **構造化タグ（`@param`・`@returns`・`@remarks` 等）を使う**：引数・返り値・前提条件が見出しで分かれ、エディタの補完・ホバー表示でも構造化して読める
- **自由形式の説明文のまま**：書く手間は少ないが、項目ごとの情報が文章に埋もれ、エディタの支援も効かない

### テストの前提・検証コメントの単位

- **各 `it`/`test` の中に個別に書く**：その1件が何を前提にし、何を検証しているかがテストコードを見るだけで分かる
- **`describe` 単位でまとめる**：重複は減るが、個々の `it` が何を検証しているかは本文を読まないと分からない

## 決定

TSDoc は `@param`・`@returns`・`@remarks` 等の構造化タグを使う形式に改める。説明文は日本語のまま書く。テストの前提条件・事前条件・検証項目は、各 `it`/`test` の中に個別にコメントで書き、`describe` 単位でまとめない。

既存の `utils/`・`components/`・`entrypoints/` 全体と、全テストファイルに遡及適用する。

## 結果

- エクスポートされた型・関数・コンポーネントの契約（引数・返り値・前提）が構造化され、エディタの補完・ホバー表示から読み取れる
- テストの各 `it`/`test` が何を前提にし、何を検証しているかが、そのテストコードだけで分かる
- 既存コード全体への遡及適用が1回分のコストとして発生する。今後のコードは新規作成時に規約へ従うため、このコストは繰り返さない
